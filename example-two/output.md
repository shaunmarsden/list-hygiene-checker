# Hygiene Review Two: Shared Household Contact

Source: [list.md](list.md).

## Not a Duplicate, Despite Sharing Both Identifiers

**Priya Sharma and Raj Sharma** share the same email and the same phone number, which is exactly the pattern the first example treated as a confident duplicate signal (two shared identifiers). Here, the names are genuinely different, not a spelling variant of the same name, and both have their own distinct activity dates. This reads as two real people sharing a household email and phone, not one person entered twice. Do not merge these.

## What This Tests

The first worked example's confident duplicate (Rosa Alvarez / Alvarrez) had the same underlying name behind two spellings, plus shared identifiers. This case has clearly different names sharing identifiers instead. Shared contact details are strong evidence when the names also look like the same person; they are not, on their own, proof of a duplicate when the names are genuinely distinct. Flagging this as a duplicate because it superficially matches the "two shared identifiers" rule from the first example would be exactly the over-eager merge this tool exists to prevent.
